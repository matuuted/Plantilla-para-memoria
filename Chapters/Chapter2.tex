\section{Componentes de hardware del sistema}
En esta sección se describen los componentes electrónicos y módulos que conforman el hardware del sistema, entre ellos el microcontrolador, el motor de dispensado, la celda de carga y los módulos de comunicación y temporización.

\subsection{Microcontrolador STM32F446RE}

El microcontrolador empleado fue el modelo STM32F446RE de STMicroelectronics, que gestionó el dispensado de alimento, la lectura de sensores y la comunicación con los módulos periféricos.

Se seleccionó el STM32F446RE por su capacidad de procesamiento, su frecuencia de trabajo de hasta 180 MHz y su variedad de interfaces de comunicación, entre ellas UART \cite{uart_spec} ({\it{Universal Asynchronous Receiver-Transmitter}}) e I\textsuperscript{2}C \cite{i2c_spec} ({\it{Inter-Integrated Circuit}}), que permitieron integrar en un único dispositivo el control del dispensado, la lectura de sensores y la comunicación con módulos periféricos. Su compatibilidad con FreeRTOS facilitó además la organización del firmware en tareas concurrentes.

Para el desarrollo de este trabajo se utilizó la placa de evaluación Nucleo-F446RE \cite{nucleo_f446re}, que puede observarse en la figura \ref{fig:nucleo} y que integra el módulo ST-LINK necesario para la programación y depuración del microcontrolador.

\subsection{Módulo ESP32}

Para la comunicación inalámbrica con el usuario se utilizó un módulo ESP32, que actuó como puente (\textit{bridge}) entre el microcontrolador STM32 y la aplicación en PC, comunicándose con el primero mediante UART y con la segunda mediante Bluetooth.

Este módulo fue elegido por su conectividad Bluetooth integrada, que permitió implementar dicha comunicación sin hardware adicional, junto con su bajo costo y amplia disponibilidad.

El ESP32 es un SoC (\textit{System on Chip}) de Espressif Systems \cite{esp32_datasheet}, con doble núcleo Xtensa LX6 a 240 MHz y conectividad Wi-Fi 802.11b/g/n y Bluetooth 4.2, con soporte para Bluetooth Classic y BLE (\textit{Bluetooth Low Energy}). En este trabajo se utilizó exclusivamente Bluetooth Classic para la transmisión de datos en formato \texttt{JSON} (\textit{JavaScript Object Notation}). En la figura \ref{fig:esp32} se muestra el módulo, donde se distingue la antena Bluetooth integrada en el extremo superior.

\subsection{Celda de carga y módulo HX711} 
Para medir el peso del alimento en el plato se utilizó una celda de carga tipo galga extensiométrica combinada con el módulo amplificador y conversor analógico-digital HX711. La celda de carga convierte la fuerza aplicada en una variación de resistencia eléctrica de muy baja amplitud. Dado que el microcontrolador no puede procesar señales analógicas de esa magnitud directamente, se incorporó el módulo HX711 que amplifica y digitaliza dicha señal con una resolución de 24 bits. En la figura \ref{fig:hx711} se ilustran la celda de carga en la parte superior y el módulo HX711 con sus terminales de conexión en la parte inferior.

Su tasa de muestreo configurable es de 10 o 80 muestras por segundo, lo que resulta suficiente para la aplicación de monitoreo de consumo en intervalos regulares.

Su tensión de alimentación lógica es de 3,3 V a 5,5 V, mientras que la tensión de potencia para el control del motor puede ser de hasta 35 V.

\subsection{Módulo RTC DS3231}

Para la gestión autónoma de los horarios de dispensado se incorporó un módulo de reloj de tiempo real (RTC) basado en el integrado DS3231 \cite{ds3231_datasheet} de Maxim Integrated .

Este módulo se incorporó debido a su alta precisión y a su batería de respaldo, que permite conservar la hora y los horarios programados ante cortes de energía sin depender de una conexión a Internet.

El DS3231 proporciona información de fecha y hora con una precisión de ±2 ppm, equivalente a aproximadamente 1 minuto de desviación por año, y se comunica con el microcontrolador mediante el protocolo I\textsuperscript{2}C. La figura \ref{fig:ds3231} muestra el módulo, que incluye una batería de litio tipo botón CR1220 como respaldo.

\section{Software y entorno de desarrollo}

En esta sección se describen las herramientas de software y los entornos de desarrollo utilizados para la implementación del sistema, tanto para el firmware del microcontrolador como para el módulo inalámbrico y la aplicación de escritorio.

\subsection{STM32CubeIDE}

STM32CubeIDE \cite{stm32cubeide} es un entorno de desarrollo integrado (IDE) de código abierto utilizado para la programación del firmware del microcontrolador STM32F446RE. Basado en Eclipse, permite configurar periféricos, generar código inicial de forma automática, compilar y depurar en la misma plataforma.

\subsection{FreeRTOS}

FreeRTOS es un sistema operativo de tiempo real (RTOS) de código abierto ampliamente utilizado en sistemas embebidos. Provee mecanismos de planificación de tareas, semáforos, colas de mensajes y temporizadores de software que facilitan la gestión de múltiples procesos concurrentes. En este trabajo, FreeRTOS se integró como middleware sobre la capa de abstracción de hardware (HAL) del STM32 para gestionar las tareas de lectura de sensores, control del motor, comunicación UART y manejo del pulsador.

\subsection{Doxygen}

Doxygen \cite{doxygen} es una herramienta de código abierto para la generación automática de documentación a partir de comentarios estructurados en el código fuente. En este trabajo se utilizó para 
documentar el firmware del STM32 y obtener una referencia técnica en formato HTML (\textit{HyperText Markup Language}) que describe las funciones, parámetros y estructuras de datos implementadas.

\subsection{PlatformIO}

Para el desarrollo del firmware del módulo ESP32 se utilizó PlatformIO \cite{platformio}, una extensión del editor Visual Studio Code que provee soporte para múltiples plataformas de desarrollo embebido. Este entorno simplifica el acceso a las bibliotecas de comunicación Bluetooth Classic (SPP, \textit{Serial Port Profile}).

\subsection{Flutter}
\label{sec:flutter}
Flutter \cite{flutter} es un framework de código abierto desarrollado por Google para la creación de aplicaciones multiplataforma a partir de una única base de código. En este trabajo se utilizó para desarrollar la aplicación de escritorio que corre en Windows y se comunica con el módulo ESP32 mediante Bluetooth Classic. Esta aplicación permite al usuario visualizar el historial de consumo y configurar los horarios de dispensado.

\subsection{Lenguaje de programación C}

El firmware del microcontrolador STM32 se desarrolló íntegramente en lenguaje C, un lenguaje de propósito general que permite el control directo del hardware y la gestión eficiente de los recursos del sistema. Su portabilidad y compatibilidad con las bibliotecas HAL de STM32 y con FreeRTOS lo convirtieron en la opción más adecuada para este tipo de desarrollo.

\section{Protocolos de comunicación}

En esta sección se describen los tres protocolos de comunicación empleados para la transferencia de datos entre los distintos módulos del sistema. La elección de cada protocolo respondió a los requisitos 
de interfaz de cada módulo y a decisiones de diseño del sistema.

\subsection{Protocolo I2C}

Este protocolo consiste en un bus serie síncrono, bidireccional y semidúplex, organizado bajo una arquitectura maestro-esclavo. Utiliza dos líneas eléctricas: SCL para la señal de reloj y SDA para la transferencia de datos. La comunicación se basa en tramas que incluyen la dirección de 7 bits del dispositivo, un bit de lectura/escritura y un mecanismo de confirmación mediante señales ACK (\textit{Acknowledgement}) y NACK (\textit{Not Acknowledgement}) \cite{i2c_spec}.

\subsection{Protocolo UART}

El protocolo UART se utilizó para la comunicación serie entre el microcontrolador STM32 y el módulo ESP32. Este protocolo es asíncrono y utiliza dos líneas físicas: una de transmisión (TX) y otra de recepción (RX). Los datos se transmiten en tramas compuestas por un bit de inicio, los bits de datos (generalmente 8) y un bit de parada. En este sistema se configuraron ambos extremos con una velocidad de 115~200 baudios, sin paridad y con un bit de parada \cite{uart_spec}.

\subsection{Bluetooth Classic}

El módulo ESP32 gestionó la comunicación inalámbrica con la aplicación en PC mediante Bluetooth Classic bajo el perfil SPP (\textit{Serial Port Profile}). Este perfil emula una comunicación serie sobre el canal Bluetooth, lo que facilita la integración con el microcontrolador, ya que los datos recibidos por UART desde el STM32 fueron reenviados por Bluetooth, y viceversa. Los datos se transmiten en formato \texttt{JSON}, lo que permite estructurar la información de manera legible y extensible \cite{spp_spec}.
